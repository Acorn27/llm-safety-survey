| Authors | Samuel Gehman, Suchin Gururangan, Maarten Sap, Yejin Choi, Noah A. Smith | VERIFIED (same URL; arXiv https://arxiv.org/abs/2009.11462 agrees) |
| Venue | Findings of the Association for Computational Linguistics: EMNLP 2020, pp. 3356-3369, DOI 10.18653/v1/2020.findings-emnlp.301. This is a Findings paper, not main-conference. arXiv v1 24 Sep 2020, v2 25 Sep 2020. | VERIFIED, venue confirmed (ACL Anthology) |

| Size | HF: 99,442 rows, one `train` split, 67.7 MB JSON. The paper abstract says "100K". HELM's scenario docstring says 99,016 prompts, with "toxic" meaning toxicity >= 0.5. Each half carries 8 Perspective API scores (toxicity, severe_toxicity, identity_attack, insult, profanity, threat, sexually_explicit, flirtation). | VERIFIED (https://huggingface.co/datasets/allenai/real-toxicity-prompts; https://raw.githubusercontent.com/stanford-crfm/helm/main/src/helm/benchmark/scenarios/real_toxicity_prompts_scenario.py) |
| What it measures | Toxic degeneration: how likely a model is to continue a (possibly innocuous) prompt with toxic text. The 25-sample metrics come from a search-result paraphrase of the paper, not the PDF text. | Prompt/score structure VERIFIED; metric definition PARTLY VERIFIED (secondary summary) |
| Citations (Semantic Scholar, 2026-10-13) | The API returned HTTP 429 repeatedly. See the "Citation count" note at the end of this section. OpenAlex: 652. | OpenAlex VERIFIED; Semantic Scholar see note |
| Still used 2025-26 | (a) lm-evaluation-harness lists a `realtoxicityprompts` task family. The README row has no link, so the directory is unconfirmed (https://github.com/EleutherAI/lm-evaluation-harness/blob/main/lm_eval/tasks/README.md). (b) HELM repo has `RealToxicityPromptsScenario` (URL under Dataset/code). (c) The GPT-4 Technical Report reports a 0.73% toxic-generation rate on RTP; I saw this only in a search snippet, because the PDF text was unreadable. (d) Third-party model cards: the search turned up OPT and StarCoder, both pre-2024. Inspect Evals does NOT list it (https://ukgovernmentbeis.github.io/inspect_evals/). | Criticisms | (1) All labels come from the Perspective API, which the original paper itself says overestimates toxicity for minority-identity mentions and African American English. (2) Welbl et al. 2021 (https://arxiv.org/pdf/2109.07445) report that detoxification which optimises the RTP automatic metric reduces LM coverage of text about, and dialects of, marginalised groups, and that human raters often disagree with high automatic scores. (3) Perspective scores drift across API versions, which hurts reproducibility (https://arxiv.org/pdf/2305.14307, from a search summary). Anyone re-scoring RTP after that date cannot reproduce the original metric. (5) The prompts are English-only and base-model oriented. Saturation: chat models score near zero toxicity (GPT-4's 0.73% claim above; UNVERIFIED). | (1)(2)(4) VERIFIED; (3) from secondary summary; saturation UNVERIFIED |
| Researcher/blog signal | Lilian Weng, "Reducing Toxicity in Language Models" (21 Mar 2021) describes RTP: "100k naturally occurring prompts with associated toxicity scores from Perspective API". It does not mention ToxiGen or TruthfulQA. https://lilianweng.github.io/posts/2021-03-21-lm-toxicity/. ## 2. TruthfulQA (2021)

| Field | Value | Status |
|---|---|---|
| Title | TruthfulQA: Measuring How Models Mimic Human Falsehoods | VERIFIED (https://aclanthology.org/2022.acl-long.229/) |
| Authors | Stephanie Lin, Jacob Hilton, Owain Evans | VERIFIED (same URL; https://arxiv.org/abs/2109.07958) |
| Venue | ACL 2022 (60th Annual Meeting, Volume 1: Long Papers), Dublin, pp. 3214-3252, DOI 10.18653/v1/2022.acl-long.229. arXiv comments say "Accepted to ACL 2022 (main conference)". arXiv v1 8 Sep 2021, v2 8 May 2022. The first appearance is 2021 (arXiv); the formal venue year is 2022. | VERIFIED, venue confirmed |
| PDF | https://aclanthology.org/2022.acl-long.229.pdf (arXiv: https://arxiv.org/pdf/2109.07958) | VERIFIED |
| Dataset/code | https://github.com/sylinrl/TruthfulQA (Apache-2.0 code; `TruthfulQA.csv`, `data/mc_task.json`, `evaluate.py`). The repo page gives no HF link, but Inspect Evals and lm-eval use their own copies. | VERIFIED (https://github.com/sylinrl/TruthfulQA) |
| Size | 817 questions, 38 categories (health, law, finance, politics, and others). Written adversarially around common misconceptions, and filtered against GPT-3-175B (the filtering claim is from a secondary summary). Tested GPT-3, GPT-Neo/J, GPT-2 and a T5-based model; best model 58% truthful vs 94% human; the largest models were generally the least truthful. | VERIFIED (ACL Anthology abstract, arXiv abstract); filtering UNVERIFIED |
| What it measures | Truthfulness: whether a model avoids "imitative falsehoods" (false answers that are common in human text). Two tasks on the same questions. Generation is scored by fine-tuned GPT-3 judges ("GPT-judge" for truth, "GPT-info" for informativeness), plus BLEURT/ROUGE/BLEU. Multiple choice is MC1 (single true answer) and MC2 (normalized probability mass on the true set). | VERIFIED (GitHub README) |
| Maintenance changes | Oct 2021: ~300 longer reference answers added. **Jan 2025: authors fixed typos, made questions more specific, dropped invalid or LLM-incompatible ones (e.g. browsing), removed the "Indexical Error: Time" category, and added a binary-choice format with a "Best Incorrect Answer" column, which they now recommend.** They say remaining questions are not fully revalidated and old MC1/MC2 results remain largely valid. | VERIFIED (GitHub README) |
| Citations (Semantic Scholar, 2026-10-13) | 4,093. OpenAlex: 843 (different counting). | Semantic Scholar VERIFIED via API (https://api.semanticscholar.org/graph/v1/paper/arXiv:2109.07958); the API URL is the source |
| Still used 2025-26 | (a) lm-evaluation-harness task family `truthfulqa` (+ `truthfulqa-multi`) (https://github.com/EleutherAI/lm-evaluation-harness/blob/main/lm_eval/tasks/README.md). (b) Inspect Evals: "TruthfulQA: Measuring How Models Mimic Human Falsehoods", 817 samples (https://ukgovernmentbeis.github.io/inspect_evals/). (c) HELM scenario `TruthfulQAScenario`, run as multiple choice (https://raw.githubusercontent.com/stanford-crfm/helm/main/src/helm/benchmark/scenarios/truthful_qa_scenario.py). (d) Llama 2 (arXiv 2307.09288, 2023) uses TruthfulQA and ToxiGen as its automatic safety benchmarks for pretrained models, Table 11 (7B 33.29, 13B 41.86, 34B 43.45, 70B 50.18) (https://ar5iv.labs.arxiv.org/html/2307.09288). (e) Academic papers in 2025-26 still use it (e.g. https://arxiv.org/pdf/2508.19432, https://arxiv.org/pdf/2604.02574). (f) Lilian Weng's 2024 hallucination post uses it. I did NOT find a 2025-26 frontier-lab system/model card reporting TruthfulQA (a targeted search came back empty). I also could not confirm the GPT-4 Technical Report's TruthfulQA claim because the PDF text was unreadable. Nothing found for OpenAI evals. | (a)-(e) VERIFIED; frontier 2025-26 cards: NOT FOUND; GPT-4 report TruthfulQA claim UNVERIFIED |
| Criticisms | (1) Saturation/contamination: HalluLens (https://arxiv.org/html/2504.17550v1) says it is saturated, which it attributes to training-data inclusion, and also reports incorrect or overly literal gold answers. (2) A vendor guide claims MC1/MC2 >85% for current frontier models (https://futureagi.com/glossary/truthfulqa/); secondary and the model names are unchecked, so treat as UNVERIFIED. (3) Blog-level critique that the MC format rewards surface heuristics, and that time-dependent items go stale (https://turntrout.com/original-truthfulqa-weaknesses); blog, not peer-reviewed. (4) The GPT-judge scorer needs OpenAI fine-tuning access and the judge model is not released (GitHub README). (5) The authors themselves say the dataset was not fully revalidated in the Jan 2025 update. | (1)(4)(5) VERIFIED; (2) UNVERIFIED; (3) blog |
| Researcher/blog signal | Lilian Weng, "Extrinsic Hallucinations in LLMs" (7 Jul 2024) uses TruthfulQA (817 questions, 38 topics) as a core truthfulness benchmark (https://lilianweng.github.io/posts/2024-07-07-hallucination/). Stanford CRFM's HELM includes it (see above). The authors are from Oxford/OpenAI; no award found. Security venues: none. | VERIFIED |

## 3. Anthropic red-team dataset (2022)

| Field | Value | Status |
|---|---|---|
| Title | Red Teaming Language Models to Reduce Harms: Methods, Scaling Behaviors, and Lessons Learned | VERIFIED (https://arxiv.org/abs/2209.07858) |
| Authors (36) | Deep Ganguli, Liane Lovitt, Jackson Kernion, Amanda Askell, Yuntao Bai, Saurav Kadavath, Ben Mann, Ethan Perez, Nicholas Schiefer, Kamal Ndousse, Andy Jones, Sam Bowman, Anna Chen, Tom Conerly, Nova DasSarma, Dawn Drain, Nelson Elhage, Sheer El-Showk, Stanislav Fort, Zac Hatfield-Dodds, Tom Henighan, Danny Hernandez, Tristan Hume, Josh Jacobson, Scott Johnston, Shauna Kravec, Catherine Olsson, Sam Ringer, Eli Tran-Johnson, Dario Amodei, Tom Brown, Nicholas Joseph, Sam McCandlish, Chris Olah, Jared Kaplan, Jack Clark | VERIFIED (arXiv page) |
| Venue | **arXiv-only.** The arXiv page lists no venue or comments. Anthropic's blog post (22 Aug 2022) names none either. arXiv v1 23 Aug 2022, v2 22 Nov 2022. Semantic Scholar also lists the venue as "arXiv.org". | VERIFIED as arXiv-only (no peer-reviewed venue found) |
| PDF | https://arxiv.org/pdf/2209.07858 | VERIFIED (standard arXiv pattern; the abs page was fetched) |
| Dataset/code | The data is the `red-team-attempts` subset of the HH-RLHF repo: HF https://huggingface.co/datasets/Anthropic/hh-rlhf (data_dir red-team-attempts) and GitHub https://github.com/anthropics/hh-rlhf. The GitHub repo is deprecated in favour of HF and is archived/read-only as of 18 Jun 2025. Repo license shown as MIT per the repo page; check the HF card before reuse. Fields: transcript, min_harmlessness_score_transcript, num_params, model_type, rating (0-4 Likert self-rated success), task_description, task_description_harmlessness_score, red_team_member_id, is_upworker, tags (only for a random 1,000 attempts on two of four model types). Contact: redteam@anthropic.com. | VERIFIED (GitHub README) |
| Size | 38,961 red-team attacks (abstract). 3 model sizes (2.7B, 13B, 52B) x 4 model types (plain LM, prompted LM, rejection sampling, RLHF; the type names are from my knowledge of the paper, not from the fetched page). The GitHub README does not state a count. | 38,961 and 3x4 VERIFIED; model-type names UNVERIFIED |
| What it measures | Not a fixed benchmark with a score. It is a corpus of human-written adversarial conversations plus per-transcript harmlessness scores from a preference model, and the paper's finding that "RLHF models are increasingly difficult to red team as they scale" (Anthropic blog, https://www.anthropic.com/research/red-teaming-language-models-to-reduce-harms-methods-scaling-behaviors-and-lessons-learned). Harms range from offensive language to subtle non-violent unethical outputs. In practice later work uses it as a prompt source. HELM, for example, takes only the first human utterance of each transcript and evaluates the model's reply (https://raw.githubusercontent.com/stanford-crfm/helm/main/src/helm/benchmark/scenarios/anthropic_red_team_scenario.py). | VERIFIED |
| Citations (Semantic Scholar, 2026-10-13) | 904. OpenAlex: 121 (different counting). | Semantic Scholar VERIFIED via API (https://api.semanticscholar.org/graph/v1/paper/arXiv:2209.07858) |
| Still used 2025-26 | (a) HELM Safety v1.0 (Nov 2024, Kaiyom, Ahmed, Mai, Klyman, Bommasani, Liang) uses five benchmarks: BBQ, SimpleSafetyTests, HarmBench, **AnthropicRedTeam**, XSTest (https://crfm.stanford.edu/2024/11/08/helm-safety.html). (b) Research use in 2024-26, e.g. SEAS (https://arxiv.org/pdf/2408.02632, 2024) and an April 2026 automated red-teaming paper that appeared in search results (https://arxiv.org/pdf/2604.23067; content not opened). (c) NOT in Inspect Evals listing and not in lm-evaluation-harness (that harness lists `model_written_evals`, a different Anthropic dataset). No 2025-26 frontier system card citing it was found. | (a) VERIFIED; (b) first VERIFIED via search summary, second UNVERIFIED; (c) VERIFIED absence on the pages checked |
| Criticisms | (1) Static and old: attacks were written against 2022-era models with plain prompts; modern models refuse nearly all of them (UNVERIFIED as a measured claim, expected from design). (2) The adjacent HH-RLHF data was audited in "Beyond the Safety Bundle: Auditing the Helpful and Harmless Dataset" (https://arxiv.org/abs/2411.08243): the abstract says conceptualization failures and quality issues can cause harm and disparate safety behaviour across demographic groups. The abstract does not single out the red-team subset. (3) Crowdworker (MTurk/Upwork) attacks with self-rated success and preference-model scores; no ground-truth harm labels. Tags exist for only 1,000 attempts (GitHub README). (4) Contains offensive content (README warning). (5) Peer review: none. | (2)(3)(4) VERIFIED; (1) UNVERIFIED |
| Researcher/blog signal | Anthropic's own post (22 Aug 2022), same URL as above, also links a Red Teaming Policy Memo. Lilian Weng, "Adversarial Attacks on LLMs" (25 Oct 2023) says the Anthropic red-teaming dataset "contains close to 40k adversarial attacks, collected from human red teamers" and cites Ganguli et al. 2022 (https://lilianweng.github.io/posts/2023-10-25-adv-attack-llm/). CRFM: HELM Safety as above. No award found. | VERIFIED |

## 4. ToxiGen (2022, near-miss)

| Field | Value | Status |
|---|---|---|

| Authors | Thomas Hartvigsen, Saadia Gabriel, Hamid Palangi, Maarten Sap, Dipankar Ray, Ece Kamar | VERIFIED |
| Venue | ACL 2022 (Volume 1: Long Papers), Dublin, pp. 3309-3326, DOI 10.18653/v1/2022.acl-long.234. arXiv 2203.09509. | VERIFIED, venue confirmed |
| PDF | https://aclanthology.org/2022.acl-long.234.pdf (arXiv: https://arxiv.org/pdf/2203.09509) | VERIFIED |
| Dataset/code | https://github.com/microsoft/TOXIGEN; HF https://huggingface.co/datasets/toxigen/toxigen-data (needs an HF auth token). Classifiers: `tomh/toxigen_hatebert`, `tomh/toxigen_roberta`. June 2024 update added 27,450 raw MTurk annotations. License terms not stated on the page (see LICENSE.txt). | VERIFIED |
| Size | 274k toxic and benign statements about 13 minority groups; the repo's train split is ~250k; 94.5% of toxic examples were labelled hate speech by human annotators. | What it measures | Originally implicit hate speech detection (classifier training/testing). It is also used in LLM evaluation as a toxic-generation test: Llama 2 reports the percentage of toxic generations across 13 groups, using a revised prompt set that drops items where annotators disagreed on the target group (https://ar5iv.labs.arxiv.org/html/2307.09288). | VERIFIED |
| Citations (Semantic Scholar, 2026-10-13) | 676. OpenAlex: 253. | VERIFIED via API (https://api.semanticscholar.org/graph/v1/paper/arXiv:2203.09509) |
| Still used 2025-26 | lm-evaluation-harness has a `toxigen` task family: "Tasks designed to evaluate language models on their propensity to generate toxic content" (https://github.com/EleutherAI/lm-evaluation-harness/blob/main/lm_eval/tasks/README.md). Llama 2 (2023) used it. Llama-2-style follow-ups used it in 2023 (https://arxiv.org/pdf/2309.16039). NOT in Inspect Evals. No 2025-26 frontier card found. | VERIFIED for harness and 2023 reports; 2025-26 cards NOT FOUND |
| Criticisms | The repo itself says the data "can naturally be noisy", covers only implicit hate for 13 groups, and that annotations may miss context-dependence. Llama 2 had to revise the prompt set because of annotator disagreement on target group (above). Chat models score ~0% on it (Llama 2-Chat figures came from mirrored tables in a search summary, not the paper text I read), which suggests saturation; UNVERIFIED. | repo caveats VERIFIED; saturation UNVERIFIED |
| Researcher/blog signal | Lilian Weng's 2023 post mentions ToxiGen as the setting of FLIRT's text-to-text attack (https://lilianweng.github.io/posts/2023-10-25-adv-attack-llm/). Her 2021 toxicity post predates it. Microsoft research item exists; no award found. | VERIFIED |

Why a near-miss: it is widely used and well cited (676), but it started as a classifier-training dataset, it is mostly used through Llama 2's report and the harness, and the 2025-26 evidence is thinner than for the three finalists.

## Corrections to earlier notes

1. years/2022.md, TruthfulQA row: the arXiv ID 2109.07958 was marked [U]. It is now VERIFIED. Also, venue is ACL 2022 main/long, pp. 3214-3252.
2. years/2021.md, TruthfulQA row: "817 questions (count from memory)" is now VERIFIED, together with 38 categories. The repo notes were NOT mentioned before: the Oct 2021 additions and the Jan 2025 revision (questions dropped, "Indexical Error: Time" removed, new binary format). Cited 2021 and 2022 results predate the revision.
3. years/2022.md, Anthropic red-team row: authors were "Ganguli, Lovitt, Kernion, et al." The full list is 36 authors (above). "No venue confirmed" is now confirmed as arXiv-only (v1 Aug 2022, v2 Nov 2022). The 38,961 count is verified.
4. years/2022.md: the Anthropic data is described as a standalone dataset. It is actually distributed inside the HH-RLHF repository (red-team-attempts subset). The GitHub repo is archived (18 Jun 2025); HF is canonical.
5. years/2020.md, RTP row: "100K prompts" is only approximate. HF has 99,442 rows and HELM's docstring says 99,016. The note "Hosted by AI2 (toxicdegeneration.allenai.org)" is supported only by search results; HF dataset page is the verified host.
6. years/2020.md: "Weng's toxicity post is from 2021 (unverified)" is now VERIFIED: 21 Mar 2021, and it does describe RTP.
7. years/2020.md says "Later wide use in model reports is from my background knowledge". Partially checked: HELM and lm-eval-harness include it, and the GPT-4 report claim is only a search snippet. No 2025-26 frontier system card was found, so do not state that RTP is still in frontier cards.
8. years/2022.md says TruthfulQA is "included in HELM"; checked at the code level (scenario file exists). Also that ToxiGen is a "standard LLM toxicity eval (e.g., in open-model reports [U])": supported by Llama 2 (Table 11 area) and lm-eval-harness; the Llama 2 prompt set was revised from the original.
9. years/2022.md says ToxiGen measures "classifier over-flagging". The primary source describes implicit hate detection data; over-flagging was not verified.
10. Not previously noted: the Perspective API sunset (31 Dec 2026) affects reproducibility of RTP and any toxicity metric built on it.
11. Not previously noted: Inspect Evals lists TruthfulQA but not RTP, ToxiGen or Anthropic red team; HELM Safety v1.0 (Nov 2024) includes AnthropicRedTeam.
